# 비밀번호 해시 테스트 도구 설계

## 목표

`nihil-tools`에 문자열을 여러 해시 방식으로 변환하고, 원문과 기존 해시의 일치 여부를 확인하는 테스트 도구를 추가한다. 이 도구의 목적은 비밀번호를 보관하거나 인증을 제공하는 것이 아니라, 같은 문자열이 알고리즘별로 어떤 형식의 결과를 만드는지 확인하는 데 있다.

## 범위

- 앱 목록과 `/apps/password-hash-tester` 전용 페이지를 추가한다.
- `MD5`, `SHA-1`, `SHA-256`, `SHA-512`, `bcrypt`, `argon2id`를 제공한다.
- Hash 영역에서 문자열, 알고리즘, 해당 설정값을 입력한 뒤 결과 해시를 생성하고 복사한다.
- Compare 영역에서 원문 문자열과 해시 문자열을 입력한 뒤 일치 또는 불일치를 표시한다.
- 고정 해시와 salt를 사용하는 비밀번호 해시의 차이를 화면 안내로 설명한다.
- 입력값, 해시 결과, 비교 결과를 브라우저 저장소나 서버 저장소에 보관하지 않는다.

## 제외 범위

- 회원 인증, 계정 관리, 비밀번호 정책 검사
- 결과 이력, 즐겨찾기, 파일 내보내기, 공유 링크
- 암호화와 복호화 기능
- PBKDF2, scrypt 등 추가 알고리즘과 사용자 정의 salt

## 알고리즘 정책

`MD5`, `SHA-1`, `SHA-256`, `SHA-512`는 같은 문자열에 대해 항상 같은 문자열을 반환하는 고정 해시로 분류한다. `MD5`와 `SHA-1`에는 레거시 방식이며 비밀번호 저장에 사용하면 안 된다는 경고를 붙인다.

`bcrypt`와 `argon2id`는 salt를 포함하는 비밀번호 해시로 분류한다. 같은 원문이라도 매 생성 시 결과가 달라지는 정상 동작을 설명한다. 기본값은 `bcrypt` 비용 12, `argon2id` 메모리 19 MiB·반복 2회·병렬성 1로 둔다. 사용자는 비용 설정을 바꿀 수 있으나, 허용 범위 안의 정수만 사용할 수 있다.

## 화면 구성

페이지는 기존 `/apps/*`의 `UiPanel`과 `UiPanelDivider`를 사용해 세로 패널 두 개로 구성한다.

### Hash 패널

- 문자열 입력: 기본적으로 `password` 타입으로 표시하며 표시/숨김을 전환할 수 있다.
- 알고리즘 선택: 고정 해시와 비밀번호 해시를 구분한 선택 목록으로 제공한다.
- 설정: bcrypt 또는 argon2id를 고르면 관련 비용 설정만 노출한다.
- 생성 버튼: 유효한 입력일 때만 실행한다.
- 결과: 읽기 전용 해시 문자열, 복사 버튼, 알고리즘과 설정 요약을 표시한다.

### Compare 패널

- 원문 문자열과 비교할 해시 문자열을 각각 입력한다.
- 알고리즘은 해시 형식에서 식별 가능한 bcrypt와 argon2id는 자동 감지한다. 고정 해시는 사용자가 선택한다.
- 비교 버튼은 `일치`, `불일치`, `판별 불가` 중 하나를 표시한다.
- 형식이 맞지 않거나 지원하지 않는 해시이면 일치하지 않는다고 단정하지 않고 입력 형식 오류를 안내한다.

## 처리 구조

해시 계산은 Nuxt 서버 API에서 수행한다. UI 컴포넌트는 입력과 상태 표시만 맡고, 알고리즘 검증·기본값·API 요청 형식은 별도 타입 및 유틸리티로 분리한다.

서버 API는 Hash와 Compare 요청을 별도 엔드포인트로 제공한다. 모든 응답에 `Cache-Control: no-store`를 설정하며, 원문 문자열과 해시 문자열은 로그·데이터베이스·파일·세션에 기록하지 않는다. 요청 오류를 기록해야 할 경우에도 알고리즘 이름과 오류 종류만 남기고 입력값은 포함하지 않는다.

고정 해시는 Node의 암호화 API로 계산한다. bcrypt와 argon2id는 검증된 서버용 라이브러리를 사용한다. Compare는 고정 해시에서 서버가 원문을 다시 해시해 안전한 문자열 비교를 수행하고, bcrypt·argon2id에서는 각 라이브러리의 검증 함수를 사용한다.

## 오류 처리

- 빈 문자열은 허용하지 않고 입력 위치에 오류를 표시한다.
- 숫자 설정이 범위를 벗어나거나 정수가 아니면 기본값으로 조용히 보정하지 않고 오류를 표시한다.
- 지원하지 않는 알고리즘과 해시 형식은 API에서 거부한다.
- bcrypt·argon2id 라이브러리 오류와 손상된 해시 문자열은 입력 오류로 반환한다.
- 복사 API를 사용할 수 없으면 사용자가 결과를 선택해 복사할 수 있도록 결과 필드는 유지한다.

## 검증

- 고정 해시별 알려진 문자열의 결과와 같은 입력의 반복 결과가 동일함을 단위 테스트한다.
- bcrypt와 argon2id는 같은 입력으로 두 번 생성한 결과가 서로 다르고, 각각 원문 비교에는 성공하며 다른 원문 비교에는 실패함을 테스트한다.
- API 테스트로 빈 입력, 잘못된 설정값, 손상된 해시, 지원하지 않는 알고리즘을 확인한다.
- UI 테스트로 알고리즘별 설정 노출, 생성 결과, 복사 동작, Compare의 일치·불일치·입력 오류 상태를 확인한다.
- 린트와 프로덕션 빌드로 통합 확인한다.
